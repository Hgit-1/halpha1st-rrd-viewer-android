# hgit-rrd-viewer-android

在 Android 设备上查看 Rerun 记录的实验性应用。项目基于 Rerun 0.20.3，通过 Android 原生界面和系统 WebView 运行内置的 Web Viewer，提供文件打开、时间线回放和直播连接等功能。

> [!WARNING]
> 本项目在原版 Rerun 产品基础上的后续改动均由 AI 生成，尚未经过充分的人工审查与真机验证。使用前请自行评估代码与数据安全风险，仅打开可信来源的文件、连接可信的直播地址。

> [!CAUTION]
> **当前代码仍处于测试阶段，可能存在潜在的数据丢失、数据缺失、显示错误、崩溃等问题，不宜用于工作环境或生产用途。请先备份原始数据，使用副本进行测试，切勿将本应用作为重要数据的唯一保存或验证工具。**

## 主要功能

- **本地记录查看**：通过系统文件选择器打开 `.rrd` 记录，也可从文件管理器或分享菜单传入文件。
- **Rerun 原生视图**：保留实体面板、视图配置和时间线，用于查看记录中的图像、检测框、空间数据、文本日志及标量等内容；实际显示效果取决于记录格式与设备兼容性。
- **按需加载**：对可识别的记录建立帧与时间索引，根据播放位置加载部分数据，尝试降低大文件在移动设备上的内存压力。
- **小文件完整加载**：提供已知大小不超过 8 MiB 的文件完整读取选项。
- **HTTP(S) 直播**：连接兼容的 Rerun 记录流，通过本地代理向 Viewer 提供数据，并使用磁盘分段缓存接收内容。
- **移动端适配**：提供原生文件按钮，保留画布触控交互，并显示初始化、加载和运行异常信息。

## 运行要求

- Android 8.0（API 26）或更新版本。
- 支持 WebAssembly 和 WebGL 的系统 WebView，建议保持更新。
- 足够的可用内存和存储空间。大体积记录、复杂场景和长时间直播仍可能超出设备承载能力。

Viewer 的 HTML、JavaScript 和 WebAssembly 资源随 APK 打包，本地查看不依赖在线加载官方 Viewer 页面。应用启动后通过仅监听 `127.0.0.1` 的本地 HTTP 服务提供这些资源；连接远程直播源时需要相应的网络访问条件。

## 安装与使用

可在 [GitHub Actions](https://github.com/Hgit-1/hgit-rrd-viewer-android/actions/workflows/android.yml) 成功完成的构建中下载 APK 构建产物，解压后将 `RerunViewer.apk` 安装到测试设备。安装第三方 APK 时，请确认来源可信。

### 打开本地记录

1. 启动应用，点击原生文件夹按钮或 Viewer 内的打开入口。
2. 通过系统文件选择器选取 `.rrd` 文件，并按系统提示授予读取权限。
3. 等待索引和加载完成后，使用 Rerun 时间线与各视图查看数据。

也可以在文件管理器中选择“打开方式”或“分享”，将文件交给本应用。默认的分段与按需加载路径一次处理一份记录。

长按原生文件夹按钮可打开加载选项，切换小文件完整加载、停止并清空 Viewer，或连接直播。菜单还提供分段选择和检测框标识定位入口，其可用性取决于当前加载路径与文件内容；标识定位不代表数据已正确解码或时间已准确对齐。

### 连接直播

1. 长按原生文件夹按钮，选择“连接 HTTP 直播”。
2. 输入设备能够访问的可信 HTTP(S) RRD 流地址。
3. 连接后在 Viewer 中查看数据；可通过状态提示或加载菜单停止直播。

这里的直播入口接收兼容的 HTTP(S) RRD 数据流，并非任意网页、视频流或所有 Rerun 服务端协议都能直接使用。

## 数据与使用限制

- 当前基于 Rerun 0.20.3，不能保证与其他版本生成的记录兼容。默认分段路径主要处理可识别的 RRF2 `.rrd` 文件；无法安全解析或单帧过大的记录可能被拒绝加载。
- 按需加载仅在内存中保留部分数据，索引覆盖原始帧并不意味着所有行、历史状态或叠加内容都能完整显示。完整回放、时间对齐和长时间稳定性仍需真机验证。
- 内存控制措施不能保证消除内存不足、WebAssembly 分配失败或 WebGL 错误。遇到加载失败时，建议先使用更小的测试记录。
- 直播缓存会轮换并删除旧分段，不是永久录制或备份。已缓存的分段也不等于可以在同一时间线上任意回看完整直播历史；重要直播数据应由独立工具保存。
- 本地文件通常通过系统授予的 URI 读取，直播数据则会写入应用缓存。请同时评估设备存储、文件访问权限以及直播地址的安全性。

## 构建

项目使用 Shell 脚本构建 Android APK，不依赖 Gradle。默认路径面向 Termux 环境，也可在配置好 Android 工具链的 Linux 环境中运行。

需要准备 JDK 17、Android SDK 的 `aapt`、`dx`、签名工具以及 `zip`。GitHub Actions 使用 Android 31 平台与 Build Tools 28.0.3；具体环境配置可参考 [构建工作流](.github/workflows/android.yml)。

在项目目录运行：

```sh
sh build.sh
```

脚本支持通过 `ANDROID_JAR`、`SDK_FRAMEWORK`、`AAPT`、`DX`、`JAVA_HOME` 等环境变量指定工具与依赖。构建结果为 `dist/RerunViewer.apk`。

构建脚本会清空项目内的 `build/` 和 `dist/` 目录；请勿在其中保存需要保留的文件。没有本地签名密钥时，脚本会生成测试用密钥；需要覆盖安装已有版本时，应保留并使用相同的签名密钥。

常规 APK 构建使用仓库内预编译的 Viewer WebAssembly，不会重新编译 Rerun Rust 源码。`build-wasm-v100.sh` 依赖项目同级目录下另行准备的、包含相应补丁的 `rerun-source/rerun-0.20.3` 源码树，并非仅克隆本仓库即可完成的独立构建步骤。

## 测试

仓库包含帧解析、文件加载、移动端适配、播放控制和内存相关的回归测试。GitHub Actions 执行其中的 Java 与 JavaScript 测试，并构建、验证 APK；签名配置及自动构建说明见 [CI.md](CI.md)。

完整测试入口为：

```sh
sh test.sh
```

也可传入测试记录路径：

```sh
sh test.sh /path/to/recording.rrd
```

完整测试需要 Java、Node.js、Rust、`wasm32-unknown-unknown` 编译目标，以及同级的补丁版 Rerun 源码树和 `.toolchain` 相关依赖或产物。部分真实记录测试还依赖额外的参考数据。

自动化测试通过仅说明相应测试用例通过，不能替代 Android 真机上的 GPU 渲染、完整记录回放与数据完整性验证。
